# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Architecture

DreamScapes is a personalised children's bedtime-story app. It is a **plain static web app** (no bundler, no framework, no build step for the web) wrapped in a **Capacitor** native shell for iOS and Android, backed by **Vercel serverless functions**, **Supabase**, **RevenueCat**, and **OpenAI**.

There are four moving parts and they are easy to confuse:

1. **Web client** — `index.html`, `app.js` (~5.4k lines), `styles.css` (~4.1k lines), `assets/`. Vanilla JS, no modules, no transpilation. `app.js` is one large script of top-level `let` state plus `show*`/`render*` functions that imperatively rewrite DOM sections; `showScreen()` is the router. Client state persists to `localStorage` under `dreamscapes*` keys (`dreamscapesStories`, `dreamscapesAnalytics`, …). `assets/supabase.js` is a vendored supabase-js browser build, not an npm import.
2. **Serverless API** — `api/*.js`, CommonJS Vercel functions. `api/auth.js` is the shared core: every other endpoint imports `getAccountContext`, `enforceStoryAccess` / `enforceNarrationAccess`, `incrementUsage`, `sendApiError`, and `handleCorsPreflight` from it. It talks to Supabase over the REST API (`supabaseRequest` with the caller's bearer token, `supabaseServiceRequest` with the service-role key) rather than the JS SDK.
3. **Native shells** — `ios/` and `android/`, generated by Capacitor but **committed**. iOS uses **Swift Package Manager** (`ios/App/CapApp-SPM`), not CocoaPods — do not add a Podfile.
4. **Hosted site** — `www.dreamscapes.cloud` on Vercel, serving the same static files plus `/api/*`.

### How the client reaches the API

`resolveApiEndpoint()` in `app.js` decides the base URL. When running as a bundled Capacitor app (or from `file:`/localhost), it hardcodes `PRODUCTION_API_BASE = "https://www.dreamscapes.cloud"`. **Simulator and emulator builds therefore call the live production API and live Supabase data** — they are not sandboxed. Override with `window.DREAMSCAPES_API_BASE` (or per-endpoint `window.DREAMSCAPES_*_ENDPOINT`) before `app.js` loads if you need to point elsewhere.

### Plans and entitlements

Plan limits are defined in **two places** and must be kept in sync: `PLANS` in `api/auth.js` (authoritative — enforces quota server-side) and the display/gating copy in `app.js` + `index.html`. Current tiers: `free` (3 stories/mo, 10 min), `premier` (15/mo, 20 min), `plus` (30/mo, 30 min, audio, 150 audio min).

Entitlement flow: RevenueCat purchase → `api/revenuecat-webhook.js` maps the entitlement id to a plan → writes `profiles.plan` in Supabase → client reads it back via `getAccountContext`. **RevenueCat's `app_user_id` must be the Supabase auth `user.id`** or the webhook cannot match the profile. Monthly usage accrues in `usage_months`.

Supabase tables in use: `profiles`, `stories`, `usage_months`, `redeem_codes`, `redeem_code_redemptions`, `feedback_reports`, `audio_issue_reports`. SQL for some of these lives in the `supabase-*.sql` files at the repo root.

### AI endpoints

- `api/story.js` — OpenAI **Responses** API (`OPENAI_STORY_MODEL`, default set in code).
- `api/narrate.js` — OpenAI **speech** API (`OPENAI_TTS_MODEL`, default `gpt-4o-mini-tts`). Long stories are split into chunks (`MAX_CHUNK_LENGTH` 3200, `MAX_CHUNKS` 20) and synthesised with limited concurrency, then concatenated. Generated audio is cached alongside the saved story on-device so replays do not re-bill.

Both fall back gracefully to a local template story / device voice when `OPENAI_API_KEY` is absent.

## Commands

There is **no test suite, no linter, and no web build step**. Do not invent `npm test` / `npm run lint`.

Serve the web app locally:

```bash
python3 -m http.server 4173
```

Copy web assets into `www/` and sync into both native projects:

```bash
npm run mobile:sync
```

Open a native project (runs the sync first):

```bash
npm run mobile:ios
npm run mobile:android
```

Build and run on an Android emulator:

```bash
cd android && ./gradlew assembleDebug && adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Build for the iOS simulator without signing:

```bash
cd ios/App && xcodebuild -scheme App -destination 'generic/platform=iOS Simulator' -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

Store screenshots are generated by the Python scripts in `scripts/` (`build-ios-screenshots.py`, `build-ipad-13-screenshots.py`, `build-play-screenshots.py`) into `store-assets/`.

## Working in this repo

- **After editing `app.js`, `styles.css`, `index.html`, or `assets/`, run `npm run mobile:sync`.** Native projects hold *copies* under `android/app/src/main/assets/public` and `ios/App/App/public`; editing the root files alone changes nothing on device.
- **Bump the cache-busting query strings in `index.html`** (`app.js?v=…`, `styles.css?v=…`, currently `v=2026082404` / `v=2026082402`) whenever those files change, or the deployed web app and the webview will serve stale assets.
- `www/` is generated output and gitignored. `ios/` and `android/` are **not** — commit native changes.
- `scripts/build-mobile.js` copies an explicit whitelist of files (`index.html`, `support.html`, `styles.css`, `app.js`, `manifest.webmanifest`, and the `assets/` folder). **A new top-level web file will silently not ship until you add it to that list.**
- Versions are tracked separately per platform and do not match: iOS `MARKETING_VERSION` in `ios/App/App.xcodeproj/project.pbxproj`, Android `versionCode`/`versionName` in `android/app/build.gradle`.
- Secrets live only in Vercel project env vars (`OPENAI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `REVENUECAT_WEBHOOK_SECRET`, `ADMIN_EMAILS`). The Supabase URL and anon key are inlined as fallbacks in `api/auth.js`, which is expected — the service-role key is not and must never be.
- Release `.aab` artifacts have historically been left in the repo root untracked; they are build output, not source.
